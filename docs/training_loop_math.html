One training step, mathematically

Walkthrough of the loop in Part A4 of learn_the_techniques.ipynb

0. The code being explained

x = torch.tensor([[3, 7, 12, 5]] * 8)       # 8 identical sequences of 4 token ids
y = torch.tensor([4] * 8)                   # target token for each sequence
opt = torch.optim.AdamW(model.parameters(), lr=1e-3)
for step in range(30):
    logits = model(input_ids=x).logits[:, -1]   # (8, 14)
    loss = F.cross_entropy(logits, y)           # one number
    opt.zero_grad()
    loss.backward()
    opt.step()

1. Corrections to common misreadings

ReadingWhat is actually true
"model(...).logits[:, -1] turns the residual stream into logits" It runs the whole forward pass: ids → embeddings → all layers (the residual stream) → final norm → lm_head → logits. Turning the final residual stream into logits is only the last step. [:, -1] then keeps the last position's logits.
"y is the target token stream" Here y is one target token per sequence (8 numbers). In the real training the targets exist at many positions.
"opt.nograd / zero_grad stops gradient calculation" There is no opt.nograd. opt.zero_grad() clears the stored gradients; it does not stop anything. Stopping gradient tracking is a different tool: torch.no_grad().
"loss.backward() gives a number" The loss is the number. backward() fills a gradient tensor for every weight.

3. Forward pass

h = fθ(x)[:, −1]    (embed, then all layers, then final norm, last position)
z = h · WUT    (logits: one score per token id)
pik = ezik / Σj ezij    (softmax: scores → probabilities)

Row i is one of the 8 sequences. Column k is a token id (0 to 13).

4. The loss: cross-entropy

L = −(1/8) Σi log pi, yi  =  (1/8) Σi [ log Σj ezij − zi, yi ]

L is small when the model puts high probability on the correct token. Reference points:

SituationLoss
Guessing uniformly among 14 tokensln 14 ≈ 2.64
Untrained model (observed at step 0)about 3.0 (random weights, slightly worse than uniform)
Observed at step 290.03, so p(correct) ≈ e−0.03 ≈ 0.97

5. Backward: where the gradients come from

The gradient of L with respect to the logits has a very simple form:

∂L / ∂zik = (1/8) · ( pik − 1[ k = yi ] )

(1[...] is 1 if the condition holds and 0 otherwise.) Tiny worked example with three tokens, z = [2, 1, 0] and the correct token 0:

QuantityToken 0 (correct)Token 1Token 2
logit z210
probability p0.6650.2450.090
gradient p − onehot−0.335+0.245+0.090

Loss = −ln 0.665 = 0.408. The wrong tokens get a positive gradient and the right token a negative one. Updates move against the gradient, so the right logit goes up and the others go down. The gradients sum to zero across tokens.

loss.backward() carries this signal back to every weight with the chain rule:

∂L/∂θ = (∂L/∂z) · (∂z/∂h) · (∂h/∂θ)

The result is stored in each weight's .grad. New gradients are added to what is already there (.grad ← .grad + new). That is exactly why zero_grad() exists.

6. The update step

Plain gradient descent would be:

θ ← θ − η · g

AdamW (used in the code) keeps running averages of the gradient g and its square, so each weight gets its own step size:

m ← β1 m + (1 − β1) g
v ← β2 v + (1 − β2) g2
θ ← θ − η · m̂ / ( √v̂ + ε ) − η · λ · θ

m̂ and v̂ are bias-corrected versions of m and v. Defaults in PyTorch: β1 = 0.9, β2 = 0.999, ε = 1e-8, weight decay λ = 0.01. The direction is still "against the gradient"; AdamW only rescales how far each weight moves.

7. The three optimizer lines, side by side

LineWhat it doesChanges the weights?
opt.zero_grad()Clears stored .grad values from the previous stepNo
loss.backward()Computes ∂L/∂θ for every weight and stores itNo
opt.step()Applies the update rule from section 6Yes

Order matters: clear the old numbers, compute the new ones, then use them.

8. All 30 steps in one picture

repeat 30 times:
   forward  : x  -> h -> z -> p
   loss     : L = cross_entropy(z, y)
   zero_grad: wipe old gradients
   backward : compute dL/d(theta) for every weight
   step     : theta <- theta - (AdamW-scaled) eta * gradient
   (weights changed, so the next forward pass gives a lower L)
Do not picture "making the residual stream". Each step changes the weights θ. The residual stream changes only as a result. And nothing here generalizes: the demo teaches one sequence to produce token 4, which is why the loss reaches about 0.03.

9. Where "stopping gradients" actually lives

ToolEffectUsed for
torch.no_grad()No gradient tracking inside the block; weights cannot learn from itMeasuring: accuracy, patching, probes
.detach()Cuts one tensor out of the gradient graphCopying an activation out (hook demo)
model.eval()Turns dropout off. It does not stop gradientsRepeatable measurements

In COCONUT training, loss.backward() sends the learning signal back through the fed-back thoughts. If a thought were detached, the signal would stop there: the model could use the thought but could not learn to improve it. Patching (Part F) runs under no_grad because it tests a trained model.
